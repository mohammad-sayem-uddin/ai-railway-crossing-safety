## 6. Reconciling the numbers

* Old manifest, 92 safe files: **1,801 recorded passes + 1 recorded failure = 1,802 recorded tests.** The recorded failure was `test_access_classification_tools.py::test_the_committed_manifest_matches_the_tree`, captured while the manifest was still being built. Mission 12's "1,802 tests passed" was therefore the *total recorded tests* in the old safe set, not 1,802 verified passes; the Mission 13 audit's 1,801 was the passes alone. Neither was an executed result at the time (the runner refused).
* New figure: **2,198 executed passes** = 1,727 (90 unchanged files; one more than the recorded 1,726 passes because that failed test now passes) + 471 (ten new/re-classified files: 72 + 8 + 74 + 87 + 55 + 24 + 52 + 50 + 24 + 25).
* "21 protected tests" is wrong; the excluded set is **21 files** holding 361 recorded passes and 65 recorded failures at classification time (the failures are tests that need data the guard blocked).

## 7. What this does not establish

The safe run proves the *safe set* passes with no protected read observed at Python level. It says nothing about the 21 excluded files, about real data, or about native-code reads. The classification is bound to file hashes at this moment; any later edit makes a file stale again — which is the intended behavior.
