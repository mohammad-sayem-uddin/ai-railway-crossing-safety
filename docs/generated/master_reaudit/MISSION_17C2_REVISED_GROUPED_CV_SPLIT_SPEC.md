## C2. PROPOSED lineage and eligibility evidence contract

An eligible grouping unit is an **indivisible lineage component**: approved physical-event identities linked to all camera views, segments, versions, crops, augmentations, annotations and established duplicate/source relationships that must not cross roles. A source-name key alone is not that proof. Components may combine multiple events when an explicitly approved shared-session/duplicate rule requires it; report both component count and physical-event count. No missing identity is replaced with a filename or random group.

| Evidence family (PROPOSED) | Required identity and support | Missing/conflicting evidence behavior |
|---|---|---|
| Physical event | Stable corpus/version/cohort-qualified event key, provenance/curator evidence and one canonical pass identity across views/versions | NOT VERIFIED; block certified event grouping until resolved; engine versions do not increase N. |
| Source recording / original capture | Stable source-video/capture ID, stream/camera/session and trusted identity/provenance reference | UNKNOWN origin blocks event-certified splitting; do not require an invented video for a verified independent still capture. |
| Frame / still image | Original asset ID and verified source mapping; VIDEO_FRAME needs frame index/PTS/timebase/origin evidence where applicable; STILL_CAPTURE needs capture/event provenance | A filename may identify an exported asset but cannot prove physical-event/frame identity. Missing precision is disclosed; no frame media is accessed here. |
| Derivative | Parent asset ID, transform/version/parameters and immutable ancestry links for every crop/augmentation/re-export | Orphan, cycle, conflicting parent or cross-role descendant rejects the candidate. |
| Annotation | Stable annotation ID/version, exact asset reference, source/policy/class vocabulary and eligible label provenance | Missing/orphan/conflicting annotations reject. Legitimately empty negative annotations require explicit confirmed eligibility; never infer absence from a missing file. |
| Duplicates / near duplicates | Already authorized identity/fingerprint evidence or explicit verified relationship with decision/provenance; documented uncertainty | Exact/shared-source links must be resolved into approved components or explicit approved exclusions. Unresolved near-duplicate/lineage uncertainty blocks a certified independence claim; no media hash is performed here. |
| Prior model exposure | Model/initialization/version provenance plus actual training/tuning/calibration/exposure registry for each component | UNKNOWN or KNOWN_EXPOSED prohibits independent held-out/generalization claims; a new split cannot erase past exposure. | Training eligibility | Prospective corpus-specific scientific/consent/license/provenance policy with explicit exclusions | RD-024/025 is not detector-training permission. Unapproved eligibility blocks allocation into a development pool. |
| Evaluation eligibility | Frozen final/outer/calibration/control/case-study role, metric applicability and prior-exposure limits | No role transfer based on convenient balance or an observed model outcome. Reserved components stay outside the allocator pool. |

PROPOSED component construction uses a graph of verified physical-event keys: add undirected must-link edges for the same physical event under multiple identities, shared original frame/derivative/verified duplicate relationships, and any independently adopted session-cohesion rule. Compute its connected components; identify each by its minimum exact ASCII event key and retain its sorted member set. Merely sharing a source-video filename does not prove the same physical pass; record the source relationship and apply only the explicit adopted cohesion rule. A resolved asset inherits its event component. Precomputed multi-event composite augmentations are rejected unless an explicitly adopted multi-event lineage policy provides complete links; no single event is guessed.

PROPOSED complete-join checks operate over approved safe metadata/annotation text: every eligible source image has exactly one physical-event/component mapping and an annotation disposition; every derivative resolves to its ancestors; every declared event/frame/annotation is accounted for or explicitly excluded by an adopted rule. Verify duplicate IDs, cross-corpus collisions, cohort/type mismatches and excluded-descendant propagation. No-ungrouped-fallback means absent/blank/unknown/ambiguous identity, or a configuration requesting fallback, is a hard error. Missing content identity cannot be “verified” by a warning-only stub. Evidence requiring prohibited resources is NOT VERIFIABLE here and stops the corresponding claim/allocation certification.

## C4. PROPOSED objective, feasibility and deterministic allocation

This is a completely specified **reference search algorithm**, not an implementation or a claim of practical runtime. No allocator is executed and no synthetic or real assignment manifest is generated in C2. T03 may later accept this bounded reference contract or require a separately reviewed equivalent scalable algorithm; no library/version is silently selected.

<a id="c4-1"></a>

### C4.1. PROPOSED freeze inputs and report feasibility before selecting K

1. Freeze corpus/role/lineage/eligibility/annotation/class/stratum/exposure metadata and its approved evidence bindings. Build aligned component records before sorting; each record contains its full label/count vector. No separately shuffled labels.
2. Define approved class support constraints and nuisance coverage objective, including unknowns and unit/weighting, **before choosing K**. Candidate K values are supplied for feasibility review; no built-in five-fold default or silent K reduction. R03/R06 own scientific roles/claims; T03 selects the algorithm/objective and a reviewed candidate K after feasibility evidence.
3. For any candidate K, require integer K≥2 and at least K eligible indivisible components, nonempty folds and declared per-role support. Compute physical-event/component/frame counts, label support, unknown counts, reserved conflicts and lineage completeness. No candidate exists if prerequisite identities/roles are unverified.
4. Distinguish coverage modes. EVERY_FOLD_COVERAGE requires each explicitly selected stratum/class to occur in every OUTER_EVAL fold; at least K distinct eligible **components** supporting that stratum is a necessary condition. It is not sufficient under mixed labels/other constraints. APPROXIMATE_GROUPED balances observed dimensions without promising every-fold coverage; a rare stratum may legitimately be absent from some folds, which must be reported. Unknown is a disclosed missingness category, not invented weather/lighting/direction.
5. Produce a feasibility finding per candidate: NO_VERIFIED_INPUT, NECESSARY_CONDITION_FAILED, FEASIBLE_OPTIMAL, INFEASIBLE_EXHAUSTIVE or UNDETERMINED_BUDGET. Only exhaustive hard-constraint search can use INFEASIBLE_EXHAUSTIVE. Missing labels or exhausted search budget never prove all five-fold grouping impossible. No run changes K, role, label, group, support constraint or coverage mode to force success.

VERIFIED missingness scope: safe metadata parsing in this mission found none of weather/lighting/direction as top-level keys in the 27 V2 inventory entries; V1 dataset-level metadata does not establish the required event join. This does not assert those labels exist nowhere. The original hypothetical23/5 sizing is arithmetic only;23 is not a verified development group count (`docs/generated/master_reaudit/MISSION_17B_GROUPED_CV_SPLIT_DESIGN.md:296-298`; `docs/generated/master_reaudit/MISSION_17C1_INDEPENDENT_CHALLENGE_OF_17C0.md:478-495`).

<a id="c4-2"></a>

### C4.2. PROPOSED exact search / tie-breaking / stopping

Input consists of eligible components g1…gM, sorted by exact ASCII group_id, and a **single** candidate K, selected_features, hard support/role constraints, integer node_budget≥1 and seed=null. No randomness is used; non-null seed or ungrouped_fallback=true is rejected under this candidate contract. Each component has verified physical_event_ids, event_count e_g (distinct canonical physical events), frame_count f_g (distinct eligible original VIDEO_FRAME/STILL_CAPTURE assets; derivatives/annotations do not inflate this count) and integer counts c_gs of physical events carrying each selected feature s. A nuisance/class presence count is not interchangeable with object-box count; policy defines all feature counts prospectively.

For an assignment vector a in[0…K−1]^M, compute E_j=sum(e_g assigned j), C_js=sum(c_gs assigned j), F_j=sum(f_g assigned j), and global totals E,C_s,F. Minimize the lexicographic tuple:

    ( sum_j(K*E_j−E)^2,
      sum_s sum_j(K*C_js−C_s)^2,
      sum_j(K*F_j−F)^2,
      assignment_vector_in_sorted_group_order ).

This PROPOSED objective prioritizes physical-event balance, then the preselected feature distribution, then frame-count balance; the final assignment vector breaks all ties deterministically. Hard constraints (identity, no fallback, nonempty roles, required support/coverage and exclusions) always outrank the objective. This is a declared choice pending T03, not a statistical optimality/generalization guarantee.

PROPOSED reference procedure: traverse the full prefix tree in depth-first order; extend the next sorted component with fold indices0,1,…,K−1 in that order. Count every visited prefix, including the root, as one node. No unstated randomized branch ordering, symmetry pruning or heuristic early acceptance is permitted. At each complete leaf, evaluate the hard constraints applicable to that run level from the frozen role policy; invalid leaves are discarded. OUTER runs map assigned fold to OUTER_EVAL and its complement to OUTER_TRAIN_POOL; INNER runs map assigned fold to INNER_TUNE and its complement to INNER_TRAIN. Only the corresponding Support rules are applied at that level; outer-evaluation exclusions always apply to inner inputs. EVERY_FOLD_COVERAGE targets OUTER_EVAL for an outer run and INNER_TUNE for an inner run. Compute the exact integer objective at each valid leaf and retain its lexicographic minimum. If all nodes are exhausted with no valid leaf, report INFEASIBLE_EXHAUSTIVE. If all are exhausted with a minimum, report FEASIBLE_OPTIMAL. If the next node would exceed node_budget, report UNDETERMINED_BUDGET and publish **no accepted assignment**, even if an incumbent exists; an optional diagnostic incumbent is explicitly non-accepted and never written as a split manifest. A time limit is not substituted for the deterministic node budget.

This exhaustive reference may be exponential and impractical for a large corpus. Its role is a precise auditable specification and small synthetic reference, not an assertion that it scales to1,315 groups. A scalable solver/proof/canonical tie policy and resource budget are a remaining T03 question; equivalent hard constraints/objective must be evidenced before substitution. Metadata count alone supplies no such runtime evidence.

<a id="c4-3"></a>

### C4.3. PROPOSED outer/inner allocation and verification

Freeze the chosen outer assignment without model feedback. For each outer fold i, OUTER_EVAL is exactly groups assigned i; OUTER_TRAIN_POOL is its DEVELOPMENT_POOL complement. If tuning_mode=INNER_GROUPED, repeat the same deterministic reference procedure with the declared inner K/configuration using only that complement, recomputing its counts and support feasibility. Inner assignments reference the immutable outer-assignment digest. If tuning_mode=FROZEN_RULE, no inner split is generated and the prospectively frozen training/threshold/early-stopping rule digest is mandatory. Neither mode may inspect outer outcomes. No automatic choice between them exists. Outer FEASIBLE_OPTIMAL establishes only that outer run, not inner feasibility. Every required inner run must independently complete successfully before an accepted nested payload exists; an inner failure/budget limit blocks publication of the whole candidate. It does not prove that every alternative outer partition/nested plan is infeasible. There is no automatic reshuffle, role change or K reduction; the unresolved design returns to T03/R03/R06.

PROPOSED acceptance verification recomputes all group/image/annotation/derivative joins, pairwise role intersections, exactly-once outer coverage, reserved exclusions, inner-subset constraints, class/nuisance/unknown counts, objective and deterministic order from the bound inputs. It does not merely re-read assignment dictionaries for duplicate keys. Input-order permutation must yield identical canonical assignments; unknown/orphan/conflicting lineage must fail closed. Existing tests demonstrate only specified old behavior, including an explicit fallback branch (`tests/unit/test_split.py:25-72`); they are not run here and do not validate this new design.

## C6. PROPOSED tuning, calibration and reporting boundaries

PROPOSED: choose thresholds, preprocessing, hyperparameters, early stopping and checkpoints only inside the declared outer training/inner tuning process or prospectively frozen rule. Calibration mode NONE fits no new score-calibration transform; INNER_OOF fits the frozen calibration rule only to inner out-of-fold scores bound to their fold/model provenance; RESERVED_CALIBRATION fits only the explicitly reserved CALIBRATION_ONLY components. A final refit may use the outer training pool only under the frozen rule, and cannot claim former training/tuning/calibration cases are unseen. All selections and transforms remain disjoint from OUTER_EVAL; no outer result may select among them. Fit preprocessing on training inputs only. Reinitialize/retrain with recorded permissible model provenance for each outer iteration; a preexisting checkpoint's unknown exposure cannot be corrected by relabeling its new test set. The required model provenance is NOT VERIFIABLE in C2 because checkpoints are prohibited.

PROPOSED: calibration/control/case-study roles are frozen prospectively under R03/R06. An adopted development calibration set may be used within its allowed scope; independent evaluation controls cannot be reused for model/threshold selection. If reused, describe results as exploratory and disclose the selection.
