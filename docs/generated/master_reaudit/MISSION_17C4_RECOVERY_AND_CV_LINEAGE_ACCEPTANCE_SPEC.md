## 1. Record bytes, ownership and linearization

RC01. Use canonical UTF-8 JSON: sorted ASCII object keys, no whitespace/BOM, no JSON floats, minimal integers with booleans distinct, exact decimal strings/rational pairs, preserved Unicode scalar text without normalization, quote/backslash escapes, U+0000…001F as lowercase six-character escapes, other scalars literal UTF-8. Reject duplicate/unknown keys, invalid Unicode and noncanonical bytes. Set arrays have type-specific sorted unique keys; order-bearing arrays preserve order. Cross-language golden vectors must cover every representation. Generic JSON defaults do not by themselves implement this codec.

RC02. RecordBody has exactly schema_version, session_id, record_id, operation_id, sequence, kind, actor_principal, role_binding, approval_binding, grant_binding, assignment_binding or null, phase_binding or null, protocol_binding, execution_binding, previous_record_digest and content. kind is GENESIS, OBSERVATION, CORRECTION, EXPOSURE, ADJUDICATION, RECOVERY, FINALIZE or ABORT. Content is a separately closed type by kind; human kinds require AB11–AB13 fields, exposure requires both source-seal digests and monotone knowledge version, terminal content references only the prior committed head; the resulting terminal digest/head is stored outside its own body in the authority receipt, avoiding self-reference. Genesis sequence=0 and previous_record_digest=null (no zero-hash sentinel); every later sequence=prior+1 and previous_record_digest is the exact prior envelope digest. Genesis content binds grant/session/project/policy and initial fence. Body excludes all computed digests and attestations.

Content schemas are closed: GENESIS={grant_id,nonce_digest,project_binding_digest,policy_binding_digest,initial_fence,created_at_utc}; OBSERVATION={observation}, CORRECTION={correction}, ADJUDICATION={adjudication}, whose nested closed types are AB11/AB12/AB13. EXPOSURE={case_assignment_key,first_seal_digest,second_seal_digest,no_second_decision_digest,previous_knowledge_version,next_knowledge_version,exposure_kind,actor_disclosure,exposed_at_utc}; exactly one of second_seal_digest/no_second_decision_digest is non-null, and next_knowledge_version=previous+1. RECOVERY={previous_fence,new_fence,expected_anchor,source_operation_ids,reconciliation_outcomes,reason,recovered_at_utc}; new_fence>previous_fence, outcome entries are {operation_id,request_digest,state,receipt_ref}, where receipt_ref is non-null exactly for known committed outcomes. FINALIZE={outcome,prior_committed_head,record_count_before_terminal,open_operation_count,closed_at_utc}, with open_operation_count=0. ABORT={reason,prior_committed_head,aborted_operation_ids,unknown_external_ids,aborted_at_utc}; unknown outcomes remain quarantined/auditable even after client abort and cannot be promoted. IDs/digests/versions have the reference types above, count/fence/sequence fields are nonnegative integers excluding bool, timestamps are canonical UTC strings, and unknown keys reject. Authority-maintained abort/revocation audit after client revocation uses its independently permitted administrative audit operation, never the revoked client's protected-resource permission.

ActorAttestation={mechanism,credential_ref,body_sha256,proof_bytes,authentication_session_ref}. mechanism must resolve to the future adopted verification policy and credential trust, proof_bytes is canonical base64 (or an explicit registered recorded-statement type under the cooperative profile), and body_sha256 must match this body. The selected trust profile determines which mechanisms are accepted; unsupported/unverifiable proofs deny. No signature infrastructure is claimed to exist. Typed keys referencing approval, grant, appointment, assignment and execution content must resolve to their AB schemas and trusted expected versions before acceptance.

RC03. body_sha256=SHA256(canonical body). A detached actor attestation binds that digest and approved mechanism/issuer. Envelope has exactly body, body_sha256, actor_attestation; record_digest=SHA256(canonical envelope). Wrapper has exactly envelope, record_digest, followed by one un-hashed newline for framing. Anchor contains session_id, sequence, record_count, byte_length, final_record_digest, authority_version and current_fence. Record count includes genesis. Authenticate expected anchors independently; a locally self-consistent chain cannot prove identity, truth or absence of rollback.

RC04. Authority serializes reservation, prepare, revocation, lease/fence change, commit and finalize for each affected session/grant using linearizable transactions. Operation states are PREPARED, COMMITTED, ABORTED and UNKNOWN_EXTERNAL. No operation may have two content digests. query(operation_id, authenticated principal) returns exact state, bound digest and immutable receipt or absence; querying never re-executes a side effect. A lease takeover increments the monotone fence; stale owners may damage writable local files but cannot obtain broker use or authoritative commit. Stable-inode local locking is cooperative serialization only.

RC05. Commit order is: (1) current actor/approval/binding/phase/quota check and PREPARED reservation; (2) durable protected payload journal containing exact candidate bytes/content digest; (3) local create-only append under the same stable-inode read-head/validate/append lock and fsync, plus directory fsync on creation; (4) authority commit CAS rechecks grant/time/revocation/fence/session ACTIVE/expected head and atomically advances anchor, quota/knowledge state and COMMITTED receipt; (5) ACK. Steps2/3 may each leave recoverable uncommitted data; neither alone is success. ACK is forbidden until both protected payload and local append are durable and authority commit is durable. An alternate protected storage architecture must prove equivalent recoverable payload durability before acceptance, not silently omit it.

RC06. Revocation linearizes by incrementing current revocation version before returning success. Commit after that point must abort PREPARED work if it relies on the revoked authority, even if local append already occurred. A commit that linearized first remains historical COMMITTED; revocation blocks future actions and handle reuse but cannot revoke disclosed bytes. Finalize atomically requires ACTIVE and no outstanding PREPARED/UNKNOWN_EXTERNAL operations; it may return BUSY and must be retried only as authorized. Finalize commit writes the terminal receipt/head and blocks all later prepares/commits. Abort marks remaining PREPARED operations ABORTED, preserves/quarantines their bytes and never unreserves the grant. No arbitrary in-flight IO cancellation is promised.

RC07. Crash recovery authenticates the same principal/session/project/bindings, a still-valid grant/roles, a fresh exclusive fence and trusted current anchor. COMMITTED but ACK-lost returns the same receipt and never appends again. PREPARED with exact protected bytes may finish only via an explicitly authorized recovery transaction with fresh checks; revoked/expired or changed-content candidates abort/quarantine. A local suffix without matching PREPARED journal cannot be adopted. Missing local COMMITTED bytes are restored from protected journal only via audited recovery that preserves the authoritative bytes/head; missing protected payload is an incident, not a reset from local state. Torn suffix/mid-file corruption is preserved and quarantined. Never truncate acknowledged history silently.

RC08. External effects use a separate content-bound idempotent transaction. No local ledger can provide global exactly-once IO. Missing external outcome becomes UNKNOWN_EXTERNAL; it blocks finalization/publication until an independently verified receipt resolves it, otherwise quarantine. Promotion visibility uses the single protected batch-manifest commit point from AB15, with revocation/fence/approval recheck. Staging objects alone remain non-authoritative. Replay with exact committed batch returns receipt; different bytes under the same ID conflict.

RC09. Pure security requirements remain blueprint-only. Future synthetic cases must cover every crash cut between RC05 steps, simultaneous prepare/revoke/commit/finalize orderings, stale owners, ACK loss, journal/local loss, torn suffix, quota/knowledge atomicity and authority compromise. The system denies unknown authority state and reports availability loss; it makes no administrator-compromise or physical-railway guarantee.

## 2. Closed typed lineage registry and reference graph

CVL01. The general candidate corpus registry contains versioned immutable tables and no implicit path loading. Binding={artifact_id,version,digest,provenance_role,evidence_status,authority_ref}; status is VERIFIED, NOT_VERIFIED or NOT_VERIFIABLE. Accepted scientific evidence requires actual trusted resolution, not a flag. The deterministic input-reference DAG contains only preexisting input evidence; allocation payload then references inputs; output validation receipt references payload; authenticated execution/approval receipt references payload and validation. No output receipt is required as its own hashed input. A resolver rejects unavailable/conflicting versions, unsupported provenance roles, cycles or mismatched digests. This contract does not cause protected evidence to be accessed.

CVL02. PhysicalEvent has canonical_event_id, dataset/version/cohort, exact aliases, immutable curator/provenance binding, prospective dataset_role, weather/lighting/direction MetadataValue, declared labels with policy/provenance and exposure records. MetadataValue is {value:string or null, unknown_reason:string or null, provenance_ref}; exactly one value/unknown_reason is populated. Unknowns remain unknown. Alias table is a function to one canonical pass; conflicting aliases reject. Physical-event counts count canonical passes once, not aliases or engine versions. No railway train_events category is detector-training permission.

CVL03. Capture has capture_id, sorted event_ids, camera_id/crossing_id/session_id MetadataValues, original_capture_type VIDEO/STILL, clock/timebase/origin evidence and provenance bindings. A recording may contain multiple events; capture identity alone does not merge unrelated passes. Asset has asset_id, canonical_event_id, capture_id or null, kind ORIGINAL_FRAME/STILL/DERIVATIVE/ANNOTATION, parent_asset_ids, frame_index/PTS/timebase or explicit unavailable reason, annotation_ids, transform record or null, content_identity_ref or null, eligibility/exclusion and provenance. Annotation has annotation_id, asset_id, version, labels/explicit confirmed-empty disposition, vocabulary/policy and provenance. Every eligible asset, label and exclusion must join completely. No source filename numeral substitutes for identity.

CVL04. Transform has transform_id, version, exact canonical parameter map, parent IDs, generation_basis, fitted_artifact_refs and provenance. Derivative DAGs must be acyclic and resolve every parent. All ancestors of an accepted derivative must belong to its single canonical physical event and role; excluded parents propagate exclusion. This version rejects every multi-event composite, even if an external policy claims to permit it. Supporting plural origins requires a separately versioned schema/policy/review; no hidden extra key or guessed primary origin is permitted. Established cross-event duplicate-content identity conflicts reject until a separately approved merge/exclusion policy resolves them; known near-duplicate uncertainty blocks independent claims.

CVL05. FittedArtifact={artifact_id,kind,model_initialization_ref,version,parameters,fit_event_ids,selection_event_ids,parent_artifact_ids,score_sources,provenance}. kind is BASE_MODEL, PREPROCESSOR, CALIBRATOR or FEATURE_CACHE. Every parent resolves in an acyclic artifact DAG. FEATURE_CACHE binds producing model/transform and its inherited fit/selection membership, not just cached sample IDs. OOF score sources bind event, prediction, generating model, inner fold and exclusion of that event from the model's fit/selection sets. Unknown prior model exposure prohibits independent-held-out claims. Access permissions and lineage certification are distinct; no model/cache bytes are loaded to satisfy this specification.

CVL06. Roles are DEVELOPMENT_POOL, OUTER_EVAL, OUTER_TRAIN_POOL, INNER_TRAIN, INNER_TUNE, CALIBRATION_ONLY, RESERVED_CONTROL, CASE_STUDY and FINAL_DESCRIPTIVE. Parent OUTER_TRAIN_POOL contains its inner subsets intentionally. Pairwise sibling disjointness applies within an iteration; exactly-once outer evaluation covers eligible development components. All descendants inherit the event/component role. Shared camera/site background limits independence and is not proof of same event. Optional session-cohesion merges require approved explicit policy before allocation; absent policy cannot silently relax grouping.

## 3. Explicit bounded synthetic allocator profile

CVL07. Mission17D implements only SYNTHETIC_GROUPED_V1, a separately named in-memory engineering profile. It is not a replacement adopted for C2 LEX_DFS_REFERENCE_V1 and never claims its exact global optimum. Inputs use synthetic: IDs and explicitly constructed Python metadata; no loader, checkpoint operation, official manifest writer or real-corpus CLI is exposed. Namespace checks are an accident guard, not proof of provenance/authentication. Real V1/V2 lineage, adoption and X06 remain pending. The generic full registry above is the future researcher-review contract; 17D implements the metadata subset required for its documented synthetic grouping/role tests and must list any deferred registry fields honestly.

CVL08. Validate canonical event identities/aliases/capture/asset/transform/annotation relationships first. Reject absent/ambiguous/conflicting IDs, duplicate IDs, orphan/cyclic lineage, multi-event descendants, missing original assets/annotation dispositions, unknown roles or requested fallback. Exclude reserved/control/calibration/case-study/final components from DEVELOPMENT_POOL by explicit role. No invented class labels; a supplied empty label set is distinct from a missing/unverified label disposition. Engine/control labels do not automatically assign roles: supplied prospective policy does, preserving RD024 pooled exclusion and RD025 confirmation/reporting direction.

CVL09. For declared K≥2 and each required label's minimum m≥1, require at least K nonempty eligible physical components and at least K*m distinct supporting eligible events per every-evaluation-fold label. These are necessary conditions only. Feasibility output distinguishes INVALID_INPUT, INFEASIBLE_NECESSARY, FEASIBLE_GREEDY, FEASIBLE_SEARCH, INFEASIBLE_EXHAUSTIVE and UNDETERMINED_BUDGET or UNDETERMINED_SIZE. No invalid/undetermined/infeasible result contains an accepted assignment. All labels/support/roles/K are frozen inputs; no automatic K/stratum/role reduction or ungrouped fallback occurs.

CVL10. Sort components by decreasing original asset count then canonical event ID. Greedily place each in the fold minimizing the tuple (resulting sum of squared event-count imbalance, supplied-label imbalance, original-frame imbalance, fold index), computed from complete aligned records using integers. If the resulting nonempty partition satisfies every required support constraint, return FEASIBLE_GREEDY and recomputed objective/coverage; it is deterministic, not globally optimal. Cost is O(M*K*(L+1)) plus lineage validation/sorting; implementation must not enumerate K^M on this path. Synthetic metadata with thousands of events may test operation and grouping without generating a research split.

CVL11. If greedy constraints fail and M≤18, search a deterministic depth-first assignment tree in the same component/fold order, bounded by an explicit positive integer node budget. Count root and each visited prefix. Prune empty-fold impossibility and label-support capacity using remaining supporting events. Folds are interchangeable because constraints are identical for every fold; first-use fold-label symmetry reduction may skip equivalent labels. Return first verified feasible leaf as FEASIBLE_SEARCH, never OPTIMAL. Exhausting all canonical branches without a valid leaf proves only these frozen constraints INFEASIBLE_EXHAUSTIVE. Reaching budget returns UNDETERMINED_BUDGET; M>18 after greedy failure returns UNDETERMINED_SIZE. No time-based acceptance, random seed or implicit alternate policy is used. A small independent brute-force synthetic oracle must check feasible/infeasible classifications.

CVL12. Construct per-iteration role views only from the verified assignment and its exact complement. INNER_TUNE is an explicitly supplied group-disjoint subset of that complement; INNER_TRAIN is the remaining complement, both nonempty where used. CALIBRATION_ONLY and reserved/final/case-study groups stay outside allocator/fit/independent evaluation as defined in SC12–SC15. A final refit uses only the outer complement under an explicit frozen rule. Failed inner support/empty subsets block that candidate, not prove every nested plan impossible. 17D does not search globally across nested outer/inner plans or train anything.

CVL13. In-memory result canonicalization sorts assignments/group IDs and binds profile, input metadata, labels, K, budget, visited count, status, objective and limitations; no timestamps/host noise. Optional serialization produces a deterministic string only, with detached digest over it, not a written split. A self-declared success flag is insufficient: verifier recomputes full membership, coverage, ancestor/role joins and support from the validated registry. No human authenticity or unseen-model guarantee follows.
