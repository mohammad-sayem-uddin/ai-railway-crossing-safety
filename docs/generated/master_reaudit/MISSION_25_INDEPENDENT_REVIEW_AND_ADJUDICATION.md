# Mission 25 — Independent review and adjudication

Prepared 2026-11-05, America/New_York. Metadata/software infrastructure only; no genuine reviewer, observation, adjudication, source access or promotion established.

RD042–047 remain unchanged: external reviewer preference only if appointable; six risk-based mandatory triggers; clear-boundary risk audit with no fixed percentage; separate researcher adjudication; unresolved UNCERTAIN; deferred duration floor; hard-case pilot still a proposal.

Completion requires every declared boundary for every assigned camera and all explicit risk assessments. Uncertainty, corrections and engine-case interpretation are also derived by software, so a caller cannot bypass them by marking risk flags false. Other explicit triggers cover reviewer flags, front/back conflict and inconsistent source hashes. Independent second completion requires distinct verified physical principals, not merely different account names. Unqualified, expired, conflicted or currently unauthorized people cannot satisfy it.

Comparison uses exact measurement/state/censor/uncertainty/PTS/landmark signatures per named source and boundary, excluding free-text rationale. There is no numerical averaging and no invented tolerance. Disagreements retain every contributing observation digest and state UNCERTAIN. Corrected observations invalidate old contributor bindings. Original comparisons remain reproducible from immutable history.

Adjudication is a separate explicit submission: qualified ADJUDICATOR assignment/session, current permission, all exact contributing digests, reason and either UNCERTAIN with no value or a separately attributed human resolution observation. The adjudicator must differ from conflicting reviewers. Genuine input additionally needs authenticated human-adjudication evidence; no software resolution is generated. Versioned adjudication corrections bind the previous adjudication. Readiness rechecks current adjudicator authority and evidence. The demonstration intentionally leaves disputes unresolved and emits no adjudication.

Genuine comparison/dashboard delivery remains disabled until an authenticated, blinding-aware interface is accepted. The fixture dashboard is an engineering inspection view, never the live first-pass player. A genuine UI must withhold candidates, prior observations, predictions and comparison material until each required independent first pass is sealed; later exposure/corrections must be logged explicitly.

Adjudication resolutions cannot reuse an original observation identity or carry a separate orphan observation-correction parent. Corrections version the adjudication itself and retain all original contributors. Negative tests refuse both malformed cases before storing any adjudication.
