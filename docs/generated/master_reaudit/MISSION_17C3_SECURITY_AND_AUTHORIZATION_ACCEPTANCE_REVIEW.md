## 3. Grant bindings and session reuse

C2 required grant fields cover issuer, principal/roles, purpose/operations/resources, protocol/code/config/dependency/policy references and authority-based validity. Reservation durably binds the session and principal before access. This repairs close-time consumption ambiguity (`docs/generated/master_reaudit/MISSION_17C2_REVISED_HUMAN_REVIEW_AND_SECURITY_SPEC.md:145-164`).

| Binding | C2 sufficiency / required completion |
|---|---|
| Repository/project and actual execution state | Code/config/dependency bindings are required, but project identity, approved expected manifest schema and protected runtime origin are not fully typed. HEAD/clean-tree/disk hash alone does not authenticate loaded dependencies/ignored code or keep them immutable. Define permitted deployment identity and manifest before acceptance. |
| Protocol | Exact protocol identity and bytes are intended; final adopted version/hash must come from genuine R01 authority. Current protocol_document binding cannot silently acquire new incompatible keys/version semantics. |
| Operation/resource/purpose | Required explicit sets, per-operation checks and separate X boundaries are sound. Define qualified event/asset/handle resolution, allowable quotas/phase/case repetitions and denial for omitted operations; broad dataset scope must be an actual approval choice. |
| Human identity / session | Principal, role and session/fence bound at reservation/use; credentials/enrollment/session authentication still selected under R05/T01. Text names do not prove who observed. |
| Time | Authority time with not_before≤now<expires is specified; wrong/unavailable authority time denies use. Lease/entropy/clock freshness/skew policy remains pending, not an adopted 4h/12h value. |
| Approval record | Issuance prose requires genuine approved scope, but minimum grant list lacks required approval_record_ref/digest/subject/delegation fields and resolver. A policy reference is not proof of actual approval. C3-N01 requires an explicit immutable binding. |
| Nonce/grant/session uniqueness | Atomic authority reservation and consumed state across COMPLETED/ABORTED are correct. Session creation/initialization/idempotency must also have a unique authoritative identity; duplicate files cannot become independent valid sessions. |

One-time consumption means **one session reservation**, not one permitted operation. Repeated reads or submissions inside the same ACTIVE session are intentional if the actual approval allows them. This is not itself a replay vulnerability. It can exceed approval if a one-event/one-observation approval becomes an unlimited session grant, or if a new operation ID bypasses case/phase/quota checks. C3-N01/N02 require operation-specific eligibility and quotas/knowledge phase; idempotency only handles the same operation ID, not semantically duplicated work under fresh IDs.

The proposed lifecycle is DRAFT preparation → genuine ISSUED grant → atomic RESERVED session → ACTIVE → COMPLETED/ABORTED, with RECOVERY_REQUIRED after ownership loss. DRAFT is not authority; closure never resets consumed state. Recovery is only the same principal/session/bindings with valid current grant and fresh fence. Expired/revoked grants cannot recover. Authority unavailability denies protected use, not a local best-effort continuation.

## 5. Ledger, transactions and trusted authority

H7's digest direction is sound: canonical body excludes attestations/digests → body hash → detached actor attestation over that hash → envelope → record digest → next predecessor/independent head. There is no self-attestation hash recursion. Unicode/canonical-decimal rules are materially more precise than ordinary JSON defaults; future golden bytes are necessary because generic json.dumps does not automatically produce this custom control-character encoding. No proposed canonical encoder was implemented/tested here (`docs/generated/master_reaudit/MISSION_17C2_REVISED_HUMAN_REVIEW_AND_SECURITY_SPEC.md:168-184`).

The authority must be outside the declared attacker's write capability, not simply a second file beside the ledger. A committed anchor must bind session, sequence/count, byte length and final digest/version. Protected payload journal or immutable backup must retain exact bodies; a hash cannot recover data. Record schemas must define genesis's predecessor sentinel, set ordering, typed attestations, approval/assignment/exposure references and error variants. Current H7 does not fully prescribe these interoperability details.

For C3-N03 acceptance, a later contract must state operation outcomes such as PREPARED/COMMITTED/ABORTED/UNKNOWN (names are recommendations, not adopted schema), exact legal transitions and retry-query behavior. It must choose whether revocation aborts a prepared uncommitted operation or a defined already-linearized action completes, and order finalize against the authoritative append. If authority commits before a recoverable protected body is durable, local deletion could make an acknowledged observation unrecoverable; explicitly require durable recoverable payload before success. Distinguish an unacknowledged quarantined suffix from accepted history; never silently reset/truncate an acknowledged head. External promotion/IO requires its own idempotent commit protocol.

Point-of-use verification must cover authenticated actor/role, approval/operation/resource/purpose, case/phase/quota, session/fence, authority time/revocation and expected execution/protocol/config dependencies. The guard and resolver themselves need trusted origin. A preflight clean Git tree is useful evidence but not a host security boundary. A cooperative profile may be accepted explicitly with limitations; it cannot claim hostile same-user or administrator resistance.

## 6. Human observation integrity and publication

First and second passes exclude predictions/candidates/prior observations, revealing queue/log/player/exception state until both independent seals. External human prior exposure cannot be proved absent by software and must be disclosed. C3-N02 requires irreversible exposure/phase state across sessions and corrections. Keep original blind observations byte-identical and distinguish raw judgment, later corrected view and adjudicated outcome. No fresh ID may silently relabel informed judgment as a blind first pass (`docs/generated/master_reaudit/MISSION_17C2_REVISED_HUMAN_REVIEW_AND_SECURITY_SPEC.md:50-108`).

Risk-triggered review preserves all six source categories. CENSORED alone is not a trigger; missing trigger inputs cannot certify trigger evaluation. Corrected/hash-mismatched candidates need applicable review and integrity resolution; agreement cannot repair a media mismatch. The active source applies a proposed fail-closed trigger policy, not proof of researcher adoption or scientific tolerance (`src/railway_detection/annotation/second_review.py:6-28`; `src/railway_detection/annotation/second_review.py:170-218`). Source-inspected second-review tests cover censoring, uncertainty, identity variants and disagreements; none was run by C3 (`tests/test_mission10_second_review.py:54-103`; `tests/test_mission10_second_review.py:201-240`).

Unresolved disagreement stays UNCERTAIN; adjudication is a separate source-linked record, not overwriting or arithmetic averaging. An independently observed timestamp may equal a numerical midpoint. The inactive 8.2 proposal deliberately resolves adjudications only to OBSERVABLE/UNCERTAIN; uncontested censored/not-observable originals remain preserved. Resolving a disputed case directly to a new censored/not-observable state needs an R01 schema extension, not an invented point value. Camera-local clocks, T2 deferral, PTS evidence and honest uncertainty must survive adapter conversion (`docs/generated/master_reaudit/MISSION_17C2_REVISED_HUMAN_REVIEW_AND_SECURITY_SPEC.md:50-83`; `docs/generated/master_reaudit/MISSION_17C2_REVISED_HUMAN_REVIEW_AND_SECURITY_SPEC.md:188-205`).

Promotion requires exact approved batch, source anchors and every original/correction/adjudication/trigger/identity/protocol/schema dependency, current operation authority and qualified create-only publication. A review grant or eligibility flag never grants publication; X03 never grants X04. Current active 8.1 record expectations are incompatible with silently submitting the proposed lifecycle without a vetted versioned adapter; no dummy APPROVED status, fabricated proposal hash or fabricated attestation may bridge the gap (`src/railway_detection/annotation/stage2_1_schema.py:279-308`; `src/railway_detection/annotation/promotion_gate.py:271-310`).

Hash chains prove none of those alone. The report preserves these limits and grants nothing.
