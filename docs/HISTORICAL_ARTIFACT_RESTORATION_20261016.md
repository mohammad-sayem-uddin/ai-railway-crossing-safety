## Why this is restoration, not fabrication

Both JSON files were cross-checked against the working tree's own records before copying:

- `forensic_analysis.json` repeats the V3 run's `metrics/metrics.json` exactly (window accuracy 0.8956,
  precision 0.7875, recall 0.9692, specificity 0.8547, F1 0.869, 17 false positives, 2 false negatives,
  recording accuracy 0.8462 / F1 0.8667).
- `v1_vs_v2_comparison.json` has a V2 column equal to `RUN_20261008_AUDIO_V2/metrics/metrics.json`
  (threshold 0.28, all test metrics 1.0, 25,697 parameters) and a V1 column (threshold 0.5184,
  recording AUC 0.9645, "87 positive + 87 ESC-50 negative") equal to the figures in
  `docs/archive/AUDIO_MODEL_REPORT.md` and `AUDIO_MODEL_V2_REPORT.md`.
- Both files have the structure the generating scripts write.
- The symlink targets are relative (`43.pdf`), identical to the shadow copy; the `.pdf` files they point
  to exist in the working tree.

## Caveats and undo

- The shadow copy is an older snapshot, not a signed backup; the cross-checks above are the evidence.
  If the researcher prefers to re-derive the JSON files by re-running the training scripts, delete these
  two files first (the scripts will not re-run here: they need the original datasets and compute).
- The four `.mp3` symlinks could make globbing code see each misnamed file twice if a loader enumerates
  `*.mp3`; the manifest keys these files by their `.pdf` names and the full test suite is unaffected.

Undo (restores the previous state exactly):

```
rm experiments/audio/RUN_20261008_AUDIO_V2/metrics/v1_vs_v2_comparison.json
rm experiments/audio/RUN_20261008_AUDIO_V3_ESC50/reports/forensic_analysis.json
rm data/raw/audio/train_horn/positive/{43,44,45,46}.mp3     # symlinks only
```
